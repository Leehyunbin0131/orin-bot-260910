# 실물 로봇 테스트

운영 도메인: **ROS_DOMAIN_ID=11**. `jazzy`와 워크스페이스 환경 로드에 적용됩니다.

처음 설정하는 순서와 매일 실행할 명령은 [로봇 사용법](사용법.md)에 정리되어 있습니다.
맵 작성·저장, 호실 등록, 맥북 마이크로 음성 안내, 중단·종료와 문제 해결까지 포함합니다.

저장소를 새로 받을 때는 라이다 드라이버 서브모듈도 함께 받습니다.

```bash
git clone --recurse-submodules git@github.com:Leehyunbin0131/orin-bot-260910.git ~/ros2_ws
# 이미 복제한 경우 해당 저장소 안에서 실행
git submodule update --init --recursive
```

빌드 결과(`build/`, `install/`), 실행 로그(`log/`), 현장 지도(`maps/`)는 Git에 포함하지 않습니다.
아래의 `log/` 링크는 현재 Orin에 보관된 결과를 가리키므로 새로 복제한 환경에는 없습니다.

하드웨어·사각형 테스트용 실행 스크립트는 아래 세 개입니다. ROS 환경과 카메라 RSUSB 설정은
스크립트에서 적용하므로 `jazzy`나 별도 카메라 실행 명령을 먼저 입력할 필요가 없습니다.
테스트는 하나씩 실행합니다.

```bash
cd ~/ros2_ws
```

## 1. 하드웨어 테스트

```bash
./hardware_test.sh
```

약 30초 동안 라이다, 카메라 컬러·정렬 깊이·IMU 수신과 다이나믹셀 두 개의
통신·오류·정지 상태를 확인합니다. 기본 실행은 바퀴를 돌리지 않습니다.

바퀴를 띄워 고정한 상태에서 회전 검사까지 하려면:

```bash
./hardware_test.sh --motion --wheels-lifted
```

로그: `log/interface_tests/<실행 시각>/summary.json`

## 2. 사각형 이동 테스트

```bash
./rectangle_test.sh
```

**준비가 끝나면 실제 로봇이 출발합니다.** 기본 경로는 2m × 2m, 직진은 최대
50rpm이며 왼쪽으로 90도씩 회전합니다. 주행 공간을 확보하고 실행합니다.
중지는 실행 터미널에서 `Ctrl+C`입니다.

크기와 속도를 바꿀 때:

```bash
./rectangle_test.sh width:=1.0 height:=1.0 rpm:=15
```

바퀴 엔코더로 거리와 각도를 계산합니다. 바퀴가 헛돌면 실제 경로에 오차가 생기며,
이 테스트에는 장애물 회피 기능이 없습니다.

로그: `log/rectangle_runs/<실행 시각>/summary.json`

## 3. 센서 융합 사각형 이동 테스트

```bash
./rectangle_fused_test.sh
```

**준비가 끝나면 실제 주행합니다.** 기본 경로는 1m × 1m이며, 직진 속도 상한은
60rpm, 제자리 회전 시 바퀴 속도 상한은 25rpm입니다. 회전 속도 상한은 이전
10rpm의 약 2.5배이며, 회전 가감속과 목표 각도 접근 속도도 함께 높였습니다.
목표 거리·각도에 가까워지면 감속합니다. 중지는 `Ctrl+C`입니다.

엔코더의 전진·회전 속도, 라이다 스캔 매칭으로 추정한 위치·방향, D435if IMU의
회전 각속도를 `robot_localization` EKF(확장 칼만 필터)로 합칩니다. 주행 판단에는
`/odometry/filtered`를 사용합니다. 지도 작성과 장애물 회피는 포함하지 않습니다.

먼저 바퀴를 움직이지 않고 센서 융합을 검사하려면:

```bash
./rectangle_fused_test.sh observe:=true
```

관측 모드는 모터 토크를 끄고 입력 준비 후 30초 동안 검사합니다. 엔코더·IMU·라이다
입력과 라이다 추적 상태를 각각 확인하며, 입력 중단·시간 오류·추적 실패가 있으면
주행을 중단합니다. EKF 출력만 계속 나온다고 센서 정상으로 판단하지 않습니다.

크기·속도는 `width:=1.0 height:=1.0 rpm:=60 turn_rpm:=25`, 관측 시간은
`duration:=60`처럼 지정할 수 있습니다. `rpm`은 1~60, `turn_rpm`은 1~25이며
회전에도 `rpm` 상한을 적용합니다. 기존 테스트와 동시에 실행하지 않습니다.

로그: `log/rectangle_fused_runs/<실행 시각>/`. `events.jsonl`에 엔코더·라이다·IMU와
융합 결과를 함께 기록하고, `summary.json`에 완료 여부·모서리·정지 확인을 저장합니다.
관측 모드 PASS는 센서 융합 파이프라인 확인이며 실제 바닥 주행 정확도 검증은 아닙니다.

주행 중에는 1초마다 각 센서의 구간 이동 거리(회전 중에는 각도)를 표시합니다.
엔코더와 라이다가 충분히 움직였는데 방향이 반대이면
`Wheel/LiDAR direction mismatch`로 중단하고, 마지막 비교값을
`summary.json`의 `last_motion`에 저장합니다. 기존 5초 무진행 정지도 유지합니다.

기존 센서 장착 좌표를 재사용합니다. 두 추정기는 TF를 발행하지 않고 융합 위치를
별도 토픽으로 비교하므로, 기존 엔코더 TF와 중복 발행하지 않습니다. IMU는 각속도만
사용하며, 현재 보정 상태와 라이다 주변 형상에 따라 오차가 남을 수 있습니다.

### 반영한 배치와 치수

줄자 실측은 근사값이며, 사용자 요청에 따라 장착점은 프로파일 중심선을 기준으로
정리했습니다. 처음의 40cm 외형·구동축 전방 20cm·캐스터 좌우 15cm는 아래 정정값으로 대체합니다.

| 항목 | 모델에 반영한 값 |
| --- | --- |
| 프레임 내부 / 외부 | 40 × 40 × 40cm / 44 × 44 × 44cm |
| 프레임 구조 | 2020 프로파일 12개, 프로파일 중심선은 본체 중심에서 ±21cm |
| 프레임 밑면 / 중심 / 상단 높이 | 바닥에서 5.8 / 27.8 / 49.8cm |
| 구동륜 | 본체 중심에서 앞으로 14cm, 좌우 각각 22cm, 지름 6.5cm |
| 좌우 구동륜 중심 간격 | 44cm (기존 제어 설정 50cm에서 수정) |
| 모터 장착 기준점 | 전방 14cm, 측면 프로파일 중심선 좌우 ±21cm, 바닥에서 6.8cm |
| 캐스터 | 후방 프로파일 중심선(본체 중심에서 뒤로 21cm), 가운데에서 좌우 각각 13cm, 후방 2개 |
| 캐스터 장착축 간격 | 좌우 26cm, 구동축과 전후 35cm |
| 캐스터 바퀴 | 지름 32.4mm, 폭 14.2mm |
| 캐스터 전체 높이 / 장착판 | 42mm / 32 × 38mm |
| 캐스터 장착 구멍 간격 / 무게 | 30 × 24.3mm / 45.7g (규격 기록, 관성값으로 추정하지 않음) |
| 라이다 | 전방 프로파일 중심선(+21cm)·좌우 중앙, 바닥에서 스캔면 52cm |
| 카메라 | 전방 프로파일 중심선(+21cm)·좌우 중앙, 바닥에서 렌즈 45cm, 아래로 15도 |

구동륜 폭은 미측정으로 3cm, 캐스터 회전축에서 바퀴 중심까지의 오프셋은 1cm를
시각화용 근사값으로 사용합니다. 이 미확인 형상은 충돌 형상에 포함하지 않습니다.
캐스터는 정방향의 고정된 명목 자세로 표시합니다. 프레임 밑면 5.8cm와 캐스터 높이
4.2cm 사이의 1.6cm 간격은 단순한 지지대로 그렸습니다. 프로파일 홈, 브래킷,
캐스터 포크·판 두께·지지대 지름과 내부 장비는 단순화했습니다.
모터 장착 프레임은 프로파일 부착 기준점이며 모터 축이나 모터 외형을 나타내지 않습니다.

### 좌표 기준

`base_footprint`는 **전방 구동축 중앙의 지면 투영점**입니다. 본체 중심의 `base_link`는
그보다 14cm 뒤, 지면에서 27.8cm 위입니다. `hardware.yaml`의 센서 x/y는 본체 중심
기준이며 모델 생성 시 구동축 기준으로 변환합니다. 센서 z는 바닥 기준 높이입니다.

| 프레임 | `base_footprint` 기준 x, y, z (m) |
| --- | --- |
| `base_link` | -0.14, 0, 0.278 |
| `left_wheel_link` / `right_wheel_link` | 0, ±0.22, 0.0325 |
| `left_motor_mount` / `right_motor_mount` | 0, ±0.21, 0.068 |
| `rear_left_caster_ground` / `rear_right_caster_ground` | -0.35, ±0.13, 0 |
| `laser` | +0.07, 0, 0.52 (기존 yaw 180도 방향 보정 유지) |
| `camera_link` | +0.07, 0, 0.45 (하향 pitch 15도) |

캐스터의 `_ground` 프레임은 회전축을 지면에 투영한 기준점입니다.
카메라 내부 영상·IMU 프레임은 RealSense 드라이버가 발행합니다. 오프라인 미리보기는
이 내부 프레임을 별도로 만들지 않습니다. 기존 엔코더 TF 발행과 EKF/ICP의
`publish_tf: false` 구성은 유지합니다. 사각형 테스트의 거리·회전 기준점은 전방 구동축입니다.

```bash
cd ~/ros2_ws
jazzy
ros2 launch orinbot_hardware model.launch.py
```

이 명령은 로봇 모델·관절 상태·RViz만 실행합니다. 모터와 센서 장치를 열지 않습니다.
실제 제어 노드와 동시에 같은 ROS 도메인에서 실행하지 않습니다.
GUI가 없는 SSH 터미널에서는 HTML 미리보기를 사용하거나, 모델 노드만 실행하려면
`rviz:=false`를 붙입니다. [사용법](사용법.md)에도 정리했습니다.

### 검증과 다음 작업

- 모델 치수·센서 좌표·제어 로직의 소프트웨어 테스트 56개 통과. 같은 폴더의 `test_*.log`에 기록했습니다.
- 모의 모터 제어기와 실제 라이다·카메라를 사용해 오도메트리, 스캔, 영상·깊이·IMU의
  TF 연결과 최근 메시지 수신 검사를 통과했습니다. 실제 모터 주행은 실행하지 않았습니다.
  시작 직후 일부 오도메트리·IMU 메시지는 TF 도착 전이라 변환되지 않았습니다.
  종료 시 제어기 통계 스레드의 ROS context 종료 오류가 기록됐으며 모든 검사 프로세스는 종료됐습니다.
  [최종 TF 검사 결과](log/robot_model/20260909/tf-check.json).
- 실물 런치는 별도 `orinbot_hardware.urdf.xacro`를 사용하며 과거 시뮬레이션 모델은 유지합니다.
- 다음은 실물과 RViz의 센서 방향 대조, 새 구동륜 간격으로 직진 거리·회전각 및 센서 융합
  사각형 주행 검증입니다. TF 연결 확인만으로 위치 정확도가 검증되는 것은 아닙니다.
  카메라 내부 기준점의 세부 오차와 IMU 기본 보정값 사용도 이때 확인합니다.
- 아래 실물 SLAM과 Nav2 안내 기능을 추가했습니다. 안내용 Nav2는 구동축 기준으로
  바퀴까지 포함한 비대칭 외곽선을 사용하며, 과거 시뮬레이션용 설정과 구분됩니다.

## 거리·각도 서비스 이동

```bash
jazzy
ros2 launch orinbot_hardware motion_service.launch.py
```

별도 터미널에서 `jazzy` 후 전진 10cm를 요청하는 예:

```bash
ros2 service call /robot/move orinbot_hardware/srv/Move '{distance_cm: 10.0, angle_deg: 0.0}'
ros2 service call /robot/status std_srvs/srv/Trigger '{}'
```

접수 응답과 완료는 별개입니다. `state: succeeded` 확인 후 다음 명령을 보냅니다.
후진은 음수 cm, 좌회전은 양수 도, 우회전은 음수 도로 지정합니다.
중단은 `/robot/stop` (`std_srvs/srv/Trigger`)입니다. 엔코더 기반이며 장애물 회피는 없습니다.
호출 예시, 범위, 상태 해석, 종료 방법은 [사용법 7절](사용법.md#7-서비스-호출로-지정-거리각도-이동)에 정리했습니다.

## 웹 GUI 실물 SLAM

```bash
jazzy
ros2 launch orinbot_hardware mapping.launch.py
```

Orin 브라우저에서 `http://127.0.0.1:8080`을 열고 **새 맵 작성 시작 → 터미널 키보드
조종 → 정지 → 현재 맵 저장** 순서로 사용합니다. 맥북에서는 SSH 포워딩으로 같은
화면을 엽니다. RViz 없이 사용하며, 브라우저에는 주행 기능을 넣지 않았습니다.

`slam_toolbox`에 2D 라이다와 엔코더 오도메트리를 입력합니다. 저장은 지도 이미지·YAML과
SLAM 그래프·데이터를 함께 `maps/<저장 시각>/`에 남기며 이전 저장을 덮어쓰지 않습니다.
저장 후에도 맵 작성은 계속됩니다. `/mapping/start`, `/mapping/save`, `/mapping/status`
서비스(`std_srvs/srv/Trigger`)도 사용할 수 있습니다. 저장된 SLAM 작업을 이어 그리는 UI는
향후 작업입니다. 저장 맵을 불러와 호실을 등록하고 주행하는 기능은 아래 안내 GUI에서 제공합니다.

[사용법 8절](사용법.md#8-웹-gui로-slam-맵-만들기)에 맥북 접속·키보드·서비스·종료 방법을 정리했습니다.
실제 라이다와 모의 모터 제어기로 정지 상태의 맵 생성·연속 저장을 확인했으며,
실제 로봇 주행과 넓은 구역의 지도 정확도 검증은 아직 수행하지 않았습니다.
[검사 결과](log/mapping_verification/summary.json) · [GUI 검사 결과](log/mapping_verification/gui-summary.json).

지도 이미지와 재사용 가능한 그래프의 차이는 [SLAM Toolbox 공식 설명](https://github.com/SteveMacenski/slam_toolbox)을 참고하세요.

빌드 및 소프트웨어 테스트 70개 통과. GUI HTTP 요청과 ROS 시작·저장 연동을 검사했습니다.
[GUI 화면 예시](log/mapping_verification/gui-screenshot.png)는 실제 정지 상태 라이다 지도 데이터를 표시한 브라우저 검사 화면입니다.

## 호실 등록 · 음성 안내 로봇

모터를 켜지 않고 저장 맵에 호실을 등록하려면:

```bash
jazzy
ros2 launch orinbot_hardware guide.launch.py
```

브라우저 `http://127.0.0.1:8080`에서 맵을 선택하고, **호실 찍기 → 위치·방향 선택 →
호실 이름·별칭 입력 → 저장**으로 등록합니다. 각 맵의 `rooms.json`에 보관합니다.

실제 안내 모드:

```bash
ros2 launch orinbot_hardware guide.launch.py drive:=true
```

마지막 선택 맵을 자동으로 로드합니다. GUI에서 로봇의 현재 위치·방향을 지정한 뒤
**말하기 → 목적지 말하기 → 녹음 마치기**로 안내를 요청합니다. 노트북에서 녹음한 WAV를
Orin 내부 Whisper.cpp 한국어 지원 모델로 변환하고, 등록된 호실 하나에 대응하면
`NavigateToPose`로 목적지를 보냅니다. 편집 모드에서는 주행하지 않습니다.

맵 서버와 AMCL, 실물 크기·저속에 맞춘 Nav2 구성 및 별도 속도 차단 로직을 사용합니다.
외부 STT API와 임의 목적지 추측은 사용하지 않습니다. 실제 맵을 아직 저장하지 않았다면
맵 작성 GUI에서 먼저 저장해야 하며, 검사 지도를 운영용 기본값으로 지정하지 않았습니다.

[사용법 9절](사용법.md#9-호실-등록과-음성-안내-로봇) ·
[GUI 화면](log/guide_verification/gui-screenshot.png) ·
[Nav2 모의 주행 검사](log/guide_verification/navigation-summary.json) ·
[로컬 STT 엔진 검사](log/guide_verification/stt-smoke.json).

현재 STT는 CPU 실행이며, 내장 영어 예제 음성으로 엔진 실행을 확인했습니다. 한국어
숫자·호실 매칭은 단위 검사로 확인했고, 실제 노트북 마이크의 한국어 인식과 건물 내
주행은 아직 검증하지 않았습니다. 장애물 입력은 2D 라이다이며 카메라 깊이는 아직 추가하지 않았습니다.

안내 기능 검증: 소프트웨어 검사 77개 통과. 실제 Nav2·AMCL과 모의 바퀴·합성 라이다로
호실 도착, 최종 방향 회전, 취소 후 정지, 센서 단절 후 주행 차단을 확인했습니다.
ROS 환경을 불러온 뒤 실제 `rclpy` 컨텍스트의 도메인이 11인 것도 확인했습니다.
