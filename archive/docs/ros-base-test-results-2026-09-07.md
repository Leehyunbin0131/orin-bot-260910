# 2026-09-07 실물 ROS 주행 제어 검증 결과

바퀴를 띄워 고정한 상태에서 `/cmd_vel` → `diff_drive_controller` → 실물 Dynamixel → 엔코더 → `/odom` 경로를 검증했습니다. 최종 실물 시험은 **PASS**입니다. 카메라 IMU의 기존 커널 지원 문제는 이 베이스 제어 시험에 포함하지 않으며 여전히 미해결 상태입니다.

## 실행 조건

- 양쪽 XM430-W210 펌웨어 50. 사용자의 업데이트 완료 안내 후 실제 재조회했습니다.
- 왼쪽 ID 1, 오른쪽 ID 2, 57600bps. 방향 변환은 왼쪽 +1, 오른쪽 -1입니다.
- 바퀴 반지름 0.0325m, 간격 0.50m.
- ROS 2 Jazzy, Dynamixel 하드웨어 인터페이스 1.5.2, 실제 모터 하드웨어 사용.
- 선속도 제한 ±0.006m/s, 각속도 제한 ±0.020rad/s. 최종 모터 목표 속도 실측 최대 원시값 **14**, 측정 바퀴 속도 최대 **0.335568rad/s**입니다.
- ROS 도메인 177, 명령 만료 0.3초, 엔코더 위치 피드백 사용(`open_loop=false`).

## 실물 결과

각 단계의 명령 발행 시간은 2초입니다. 이후 명령 발행을 멈춰 컨트롤러가 스스로 정지하는지 확인했습니다.

| 단계 | 선속도 m/s | 각속도 rad/s | 엔코더 거리 m | 엔코더 회전 rad | 마지막 명령 후 정지 판정 초 |
|---|---:|---:|---:|---:|---:|
| 전진 | +0.006 | 0 | +0.012489 | +0.000698 | 0.716 |
| 후진 | -0.006 | 0 | -0.012414 | -0.000199 | 0.665 |
| 좌회전 | 0 | +0.020 | +0.000050 | +0.042476 | 0.821 |
| 우회전 | 0 | -0.020 | -0.000125 | -0.041180 | 0.818 |
| 직진+좌회전 | +0.006 | +0.020 | +0.013336 | +0.045966 | 0.819 |

정지 판정은 바퀴 속도가 모터 원시값 ±2 이내이며, 오도메트리 선속도 절댓값 0.001m/s 미만·각속도 0.004rad/s 미만인 상태가 0.25초 지속되는 것으로 검사했습니다. 표의 시간은 이 안정 구간의 시작 시각입니다. 0.3초의 명령 만료 외에 감속과 오도메트리 평균 처리 시간이 포함됩니다.

각 단계에서 바퀴 엔코더의 회전 방향과 변화량, 오도메트리의 위치·각도 변화가 일치하는지 확인했습니다. 엔코더는 오도메트리의 입력이므로 이 일치는 ROS 연결과 계산 경로를 검증한 것이며 외부 기준의 거리 정확도 검증은 아닙니다. 바퀴를 띄워 시험하여 실제 차체 이동·바닥 접지·장착 방향의 육안 확인은 포함하지 않았습니다.

추가 검사:

- 두 컨트롤러 `active`, 토크 레지스터 양쪽 1 확인 후 명령을 시작했습니다.
- 2초 지난 타임스탬프의 명령을 반복 발행했을 때 양쪽 엔코더 변화 0, 정지 유지: 통과.
- `/odom` 29.94Hz, `/joint_states` 29.99Hz, `/dynamic_joint_states` 29.99Hz.
- 위 세 토픽의 최대 수신 간격 약 0.076초. 타임스탬프 역행·반복 0건.
- 모터 통신·하드웨어 오류 표본 0건.
- `odom -> base_footprint`와 실측 센서 장착 위치 TF 확인.
- ROS 런치 정상 종료(코드 0), 양쪽 모터 정지·토크 OFF·목표 속도 0 확인.
- 기존 운영 모드 3으로 복구한 뒤에도 양쪽 목표 속도 0을 다시 기록·조회했습니다.
- 최종 소프트웨어 회귀 검증 19개 모두 통과했습니다. 부모가 종료된 뒤 남은 자식 프로세스의 정리도 포함합니다.

## 적용한 수정

1. 직진·회전을 합쳐도 확인된 저속 범위를 넘지 않도록 컨트롤러 제한을 낮추고, 런치 시작 시 바퀴 치수와 조합 속도를 검사합니다.
2. 펌웨어 45 미만의 실물 ROS 드라이버 기동을 사전 검사에서 거부합니다. 양쪽 펌웨어 50에서는 Fast Sync Read 오류 없이 동작했습니다.
3. 드라이버의 갱신되지 않는 토크 표시 대신 실제 `Torque Enable`과 `Goal Velocity` 레지스터를 `/dynamic_joint_states`로 수신해 검사합니다.
4. 모의 하드웨어에서 속도를 위치로 적분하여 엔코더 기반 오도메트리까지 검증합니다. 모의 시험에서만 제한보다 큰 명령을 발행해 제한 동작을 확인했습니다.
5. 런치 부모가 먼저 종료되어도 자식 제어 프로세스를 정리하도록 테스트 종료 처리를 수정했습니다.
6. 운영 모드 복구가 목표 속도를 초기화하는 동작을 반영하여, 기존 SDK 테스트 두 개에도 복구 후 목표 속도 0 기록·검사를 추가했습니다.
