# 성능 및 기능 검증 도구

시스템 파라미터 변경 시 성능 및 동작 변화를 정량적으로 검증하기 위한 단독 실행 스크립트 모음입니다. 별도의 빌드 과정 없이 바로 실행할 수 있습니다.

```bash
source /opt/ros/jazzy/setup.bash && source ~/ros2_ws/install/setup.bash
export ROS_AUTOMATIC_DISCOVERY_RANGE=LOCALHOST
python3 tools/<도구_명칭>.py
```

일부 도구를 제외한 대부분의 스크립트는 전체 자율주행 스택(`navigation.launch.py`)이 기동된 상태에서 실행해야 합니다.

## 측정 도구 목록

| 도구 | 주요 측정/검증 항목 | 필요 환경 |
|---|---|---|
| `measure_load.py <라벨>` | 노드별 CPU/메모리 사용량 (고정 시나리오: c070 통로 왕복) | 전체 스택 |
| `map_quality.py <라벨>` | SLAM 위치 추정 오차 및 지도 흔들림 측정 | 전체 스택 |
| `corridor_test.py [폭...]` | 통로 폭별 직진 통과 여부 및 소요 시간 측정 | 전체 스택 |
| `turnaround_test.py [폭...]` | 통로 내 제자리 회전 가능 여부 검증 (오프셋 스윕) | 시뮬레이터 전용 |
| `slam_accuracy.py` | 동작 수행 후 SLAM 추정 자세 vs Gazebo 참값(Ground Truth) 비교 | 전체 스택 |
| `stream_rates.py [초]` | 카메라 스트림별 실제 발행 주기 및 타임스탬프 동기화 상태 검증 | 시뮬레이터 전용 |
| `jump_check.py [초]` | TF 발행자 중복 여부 및 좌표계(`map->odom`, `odom->base`) 점프 감지 | 전체 스택 |
| `render_map.py` | `/map` 토픽 데이터를 PNG 이미지로 저장하고 프론티어 표시 | 전체 스택 |
| `verify_frontier.py` | 현재 지도 기준 탐사 목표 후보 지점 추출 및 검증 | 전체 스택 |
| `dock_calib.py` | 도크 비전 인식 정확도 및 회전 보정 파라미터 산출 | 시뮬레이터 + 검출기 |
| `dock_range.py` | 마커 검출 거리·편차 및 무검출 구간 측정 (거리 스윕) | 시뮬레이터 전용 |
| `dock_test.py [횟수]` | 반복 도킹 성공률 및 최종 정렬 오차 측정 | 전체 스택 |
| `dock_bench.py [--jobs N] [--repeat N]` | 여러 초기 조건(가로/각도/거리 오프셋, 파라미터 덮어쓰기)의 도킹을 **동시에** 시험 | 단독 기동 |
| `corridor_plan.py` | 통로 폭별 전역 경로 생성(Path Generation) 가능 여부 확인 | Nav2 활성화 |
| `stall_attribution.py` | 정체/비정상 정지 구간 원인 분석 (탐사/플래너/제어기/BT/기구학) | 전체 스택 |
| `path_stability.py` | 전역 경로 방향 변화량 대비 각속도 명령 부호 반전 빈도 측정 | Nav2 활성화 |
| `wrongway.py` | 경로 요구 방향 대비 역방향 회전/주행 구간 감지 | Nav2 활성화 |
| `ros_base_test.py` | ROS 제어기 기동, 엔코더·오도메트리·TF, 저속 회전·명령 만료·종료 후 정지 | 자체 베이스 기동; [사용법](../docs/ros-base-test.md) |

### 병렬 도킹 시험대

`dock_bench.py`는 다른 도구와 달리 **자체적으로 시뮬레이터를 기동합니다.** 스택이 실행 중이면 안 됩니다.

도킹 전용 런치 파일(`orinbot_navigation/launch/dock_bench.launch.py` — 시뮬레이터 + 카메라 + 마커 검출 + 도킹 노드, SLAM/Nav2 없음)을 여러 개 동시에 띄우고 각각 다른 초기 조건으로 도킹시킨 뒤 결과를 표로 모읍니다.

- 이중 격리를 적용합니다: **`ROS_DOMAIN_ID`**(ROS 2 디스커버리) + **`GZ_PARTITION`**(gz-transport). 둘 중 하나만 적용하면 인스턴스가 섞입니다.
- 격리 확인: 각 도메인에서 `/clock` 발행자가 1개씩만 보이면 정상입니다.
- 인스턴스당 약 **1 코어 / 1 GB**이므로 `--jobs`는 `nproc`과 여유 메모리를 고려하여 지정하십시오.
- 판정 기준은 동판 접촉 허용치(세로 ±48 mm / 가로 ±34 mm / 각도 ±6.3°)입니다.

```bash
python3 tools/dock_bench.py                 # 기본 케이스 묶음 (8개)
python3 tools/dock_bench.py --jobs 4        # 동시 인스턴스 수
python3 tools/dock_bench.py --repeat 3      # 케이스당 반복
```

케이스 목록은 스크립트 상단 `CASES` 항목에서 수정합니다 — 스폰 오프셋과 `docking.yaml` 파라미터 덮어쓰기를 함께 지정할 수 있습니다.

## 측정 시 주의사항

1. **CPU 사용률 측정 방식**: `ps` 명령의 `%CPU` 수치는 프로세스 시작 이후의 누적 평균값이므로 실시간 구간 부하를 측정하기에 부적합합니다. `measure_load.py`는 `/proc/<pid>/stat`의 `utime+stime` 차분을 이용하여 실시간 사용률을 측정합니다.
2. **RTAB-Map 자원 사용량 측정**: 동일 세션에서 오랫동안 지도를 누적할 경우 노드 메모리 및 CPU 사용량이 자동으로 증가합니다. RTAB-Map 관련 비교 실험 시에는 매 측정마다 스택을 새로 기동해야 합니다.
3. **테스트 시나리오 표준화**: 로봇의 물리적 제약으로 인해 갇힘이나 복구 동작이 자주 발생하는 극단적 협소 통로(0.70 m 미만)는 측정 시나리오에서 제외해야 변인을 통제할 수 있습니다.
4. **순간이동(Teleport) 시 주의**: `turnaround_test.py` 등 테스트 시 로봇을 통로 내부로 직접 순간이동시키면 정적 물체와의 초기 겹침(관통) 현상으로 인해 물리 엔진 오차가 발생합니다. 반드시 통로 외부에서 주행으로 진입시켜야 합니다.
5. **측정 스크립트 중복 실행 금지**: 복수의 테스트 스크립트가 동시에 목표 지점 액션을 전송할 경우 액션 선점(Preemption)으로 인해 검증 결과가 훼손됩니다.
6. **위치 이동 후 대기 시 스핀(Spin) 처리**: 위치를 이동시킨 뒤 대기할 때는 단순 `sleep` 대신 ROS 이벤트 스핀을 수행하여 이전 위치 메시지 큐를 처리해야 검출 한계 데이터의 오염을 방지할 수 있습니다.

## 성능 기준선 (Baseline)

### 개발 PC 기준 (상대 비교용)

| 항목 | 측정치 |
|---|---|
| CPU / 메모리 사용량 | 1.16 코어 / 1.38 GB |
| SLAM 위치 추정 오차 | 중앙값 0.027 m (90% 0.043 m) |
| `map->odom` 최대 보정량 | 0.111 m |
| 도킹 정렬 오차 (`staged`, 후진 — **현행**) | 세로 −0.7 mm, 가로 +1.8 mm, 각도 −0.13° |
| 도킹 정렬 오차 (`staged`, 전진) | 세로 중앙값 2.6 mm, 가로 1.2 mm, 각도 0.6° (중앙값 25.6초) |
| 도킹 정렬 오차 (`smooth`, 전진) | 세로 중앙값 20.3 mm, 가로 0.8 mm, 각도 0.4° (중앙값 8.6초) |
| 도크 비전 인식 정확도 (0.65 m) | 거리 오차 ~1 mm, 가로 ~0.6 mm, 각도 ~0.01° |
| 회전점 캐스터–동판 여유 (0.55 m) | 178 mm |

접촉 허용치는 세로 ±48 mm / 가로 ±34 mm 입니다. 각 수치의 도출 근거는 `docs/ros2-lessons.md` 6장을 참고하세요.
